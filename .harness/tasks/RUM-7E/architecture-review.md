# RUM-7E architecture review — final SDK review

Classification: high risk, browser privacy/security sensitive. Scope reviewed: SDK boundaries, Ingest OpenAPI 0.7.0, Storage durability semantics, RUM-7F playback, lifecycle, limits, transport and browser tests. SDK implementation review result: local gates pass; production gates in `implementation-summary.md` remain open.

1. **Policy authority:** Ingest `GET /v1/rum/replay/policy` provides exact public-credential/Origin scoped replay policy, `fresh_until` and a CORS-exposed server `Date`. Local `replay.enabled` cannot authorize capture alone. The SDK requires a fresh enabled policy before loading rrweb or continuing a promoted replay in a new document. The SDK derives a conservative monotonic deadline from the server timestamps and request timing; the clock-skew risk is closed in `implementation-summary.md`.
2. **Record/replay compatibility:** pin rrweb 2.1.6; sequence 0 requires Meta+FullSnapshot; checkpoint group eviction maintains reconstruction. Validate with real browsers and RUM-7F fixture.
3. **Data path:** only Ingest write receives replay; identity JSON is supported; Ingest compresses event array internally. 202 is durable acknowledgement. Sequential frozen-body retries match Storage idempotency.
4. **Bounded resources:** 30s/2 MiB/5000-event prebuffer is a local target; actual memory and transient copies need measurement. Upload queue, aggregate limit accounting, page/sequence limits and stopped state avoid storms. No daily quota claim.
5. **Lifecycle and durability boundary:** one semantic session identity and trigger pipeline, no duplicate replay on repeated triggers. The approved cross-document design uses metadata-only `sessionStorage` continuity. Hard navigation loses unpromoted context. A promoted replay continues under the same replay ID only after its first chunk received a valid 202 with `{accepted:true,duplicate:boolean}`; every continued document gets a new page ID and reconstruction anchor after fresh policy revalidation. If `pagehide` races the first unconfirmed upload, the SDK aborts it and persists no continuity. The next document starts a new prebuffer and requires a new semantic trigger. A request may have reached Storage without the browser receiving its response, so the old replay may remain an orphaned accepted prefix. Without retaining and retrying the exact first chunk or querying durable state through a new backend contract, the browser cannot distinguish that case. Neither payload persistence nor speculative continuation is approved. On later unconfirmed pages, metadata carries only previously accepted chunks and pages.
6. **Rollout gates:** RUM-7F private marker patch and RUM-7C real write-path E2E remain open. Privacy browser suite and local performance fixtures passed, but production workload performance needs rollout measurement. No production activation implied.

Repository process note: SDK has no Harness kernel/compiler, so this is a manual targeted review artifact, not a compiled Harness review result.
