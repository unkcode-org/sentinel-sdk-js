# RUM-7E browser replay privacy contract

Status: implementation contract; browser canary proof and limitations are recorded in `implementation-summary.md`. Raw rrweb output is sensitive. The event admission boundary sanitizes before retention, chunk sealing, logging, diagnostics, or transport. Unknown rrweb event/subtype/field is dropped or recording stops, never passed through. No `beforeSend` replay hook; the existing SDK hook is for OTel drafts and is not a privacy boundary.

## Developer contract

`data-sentinel-private` on an element is the official subtree marker. Its element/descendant text, values, attributes, DOM shape and subsequent mutations are blocked from replay. rrweb's `blockSelector: '[data-sentinel-private]'` is the base mechanism; no fallback to `ignoreSelector` (which only ignores interactions). The marker must be present **before** the initial snapshot. Adding it later cannot erase already captured material: the recorder stops and discards local buffers on any marker attribute change, and already accepted chunks cannot be recalled. Developers must mark sensitive roots in initial HTML/render and mark dynamic private nodes before attachment. The SDK replay viewer must also carry this marker.

RUM-7F follow-up in `sentinel-rum-frontend` (separate approved change): add `data-sentinel-private` to the root `<section className="replayPanel">` in `dashboard/src/features/rum/components/ReplayPanel.tsx` before recorder rollout. Test the rendered marker covers controls, candidate list and iframe; a recorder fixture embedding the panel must assert none of its text, attributes, iframe URL or mutations enter emitted/retained events. The player host is isolated already, but its parent panel currently lacks this marker.

## Capture controls and proofs

| Requirement | rrweb 2.1.6 setting / admission hook | Required proof |
|---|---|---|
| All form values, input/textarea/select | `maskAllInputs:true`; input, textarea, select and option blocked; sanitizer strips every attribute and unsupported interaction event | Initial DOM, input/change, select/textarea, dynamic insertion contain no canary |
| Visible text and contenteditable | `maskTextSelector:'*'` plus `maskTextFn` constant/length-independent masking; admission sanitizer checks every text node and text-bearing event | Static/dynamic text and contenteditable canaries absent, including length oracle check |
| Private subtrees | `blockSelector:'[data-sentinel-private]'`; pre-buffer sanitizer rejects descendant additions/updates based on blocked mirror/DOM ancestry; independent `MutationObserver` stops on marker attribute change | Initial snapshot, descendant attributes/text/input, dynamic private insertion/mutation absent; late marker stops capture |
| Risky attributes, href/src/query, inline style/CSS | Closed attribute allowlist in admission sanitizer; strip URL-bearing and text-bearing attributes, `style`, `srcset`, inline stylesheets/CSS URL/content; sanitize rrweb Meta `href` to an inert value while preserving required Meta structure; do not rely on rrweb URL normalization | Query/hash/credential canaries absent across Meta, initial snapshot and mutation events; allowed layout attrs only |
| Cookies and browser storage | No storage/console/network plugins; reject custom/plugin events; no cookie/storage APIs in recorder path | Canary values in cookies/localStorage/sessionStorage absent from all events/chunks |
| Request/response bodies and auth headers | No fetch/XHR replay plugin, no network-body plugin; reject custom events | Body/header canaries absent; replay upload request itself excluded from fetch instrumentation |
| iframe and embedded content | `recordCrossOriginIframes:false`; `blockSelector` for all iframes/objects/embeds or pre-buffer removal; `keepIframeSrcFn` must not retain URLs | Same/cross-origin iframe content and source canaries absent |
| Canvas, media, scripts and unsafe elements | `recordCanvas:false`, `inlineImages:false`, `collectFonts:false`, `plugins:[]`; block canvas/video/audio/script/style/object/embed/svg foreignObject and dynamic additions where sanitizer cannot prove safety | No canvas events/bitmap/data URLs, media URLs, script/style text, or unsafe subtree canaries |
| Shadow DOM | Test pinned rrweb behavior in Chromium/Firefox/WebKit; block shadow hosts/roots if masking and private marker cannot be proved across boundary | Open/closed shadow test; unsupported surfaces omitted, no secret leakage |
| Unknown rrweb shape | Strict v2 event admission validator/sanitizer before checkpoint buffer, bounded traversal/depth/size, safe JSON serialization | Fuzz unknown event/type/field, cyclic values, prototype keys, DOM URL and mutation canaries; fail closed |

rrweb's public guide documents `blockSelector`, `maskTextSelector`, `maskAllInputs`, checkout settings, and disabled canvas/cross-origin iframe defaults; its pinned type declarations expose these options. The guide does **not** establish that arbitrary attributes or CSS are safe. That is why the closed sanitizer and real-browser proof are release gates. Source: [rrweb recording guide](https://github.com/rrweb-io/rrweb/blob/main/guide.md).

**Security review findings:** (1) the current semantic RUM target metadata can contain bounded visible text; replay blocking is a distinct contract and must not silently change semantic RUM behavior without a separate review. (2) rrweb may put sensitive data in initial snapshots *and* mutation payloads; masking at upload time is too late. (3) URL values may appear in attributes, CSS and media; stripping only query strings is insufficient. (4) `blockSelector` semantics for dynamic insertion, shadow DOM and removed markers require browser proof. (5) no event payload, credential, identifier or sensitive selector may enter public errors or diagnostic labels. (6) any sanitizer that changes rrweb structure must be replayed through RUM-7F fixture to prove reconstruction; privacy takes precedence over visual fidelity.

Implementation review: the local negative-canary browser suite passes in Chromium, Firefox and WebKit; the separate RUM-7F marker patch and real RUM-7C write-path E2E remain rollout gates. The policy clock-skew risk was closed by the 2026-10-08 minifix and exposed Ingest `Date` contract. A failed privacy row means disable/block that surface or stop replay, never relax the privacy assertion.
