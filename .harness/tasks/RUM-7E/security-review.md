# RUM-7E security and privacy review — implementation stage

Result: implementation approved and tested; **rollout remains blocked** by the RUM-7F marker and RUM-7C real E2E. The clock-skew freshness risk is closed by the 2026-10-08 SDK minifix and Ingest's exposed `Date` header. The independent privacy contract is `privacy-contract.md`.

Threats and controls: a public key is visible and must remain a Bearer identifier, never a secret or log field; Ingest remains authority for exact Origin, credential RUM permission and environment policy. Browser cannot infer authorization from OPTIONS or frontend config. Generate UUIDs with secure crypto; retain the existing RUM session ID. Build replay URL from the validated Ingest base without query/fragment and exclude it from OTel fetch instrumentation. Sanitize rrweb events before memory retention; reject unknown shapes and prototype keys; never log raw events/chunks/DOM, URLs with queries, credentials, or payload-bearing exceptions. Do not read cookies/storage values. Bound event traversal, per-event size, whole JSON body, queue count, retry count and elapsed time. Use one in-flight upload, frozen bodies, abort on teardown, and only 202 confirmation. Do not use beacon/unload acknowledgement. Revalidate fresh policy on refresh and before each upload; server remains final authority.

Implementation evidence: Ingest OpenAPI 0.7.0 provides the browser policy discovery contract and strict bounds. Unit and Chromium/Firefox/WebKit fixtures prove default-off, masking, stripped attributes/CSS/URLs, private and dynamically inserted subtrees, marker transition fail-closed, shadow DOM exclusion, reconstructable FullSnapshots, bounded memory/queue, frozen retry bodies and cancellation. A snapshot too large for one request stops replay before upload. These tests establish the local SDK behavior, not production workload performance.

Clock-skew review: a parseable CORS-exposed server `Date` is required on each successful policy fetch. The SDK combines it with `fresh_until`, subtracts 1,250 ms for whole-second Date precision and margin, charges elapsed request/body-read time, and bounds the monotonic lease by the 120-second server contract. Missing, malformed, expired or exhausted authority stops or prevents capture. Runtime refresh, expiry and upload checks use the same monotonic deadline, so changing the browser wall clock cannot lengthen policy authority. Focused unit and real-browser tests cover fast/slow browser clocks, missing exposure and the server freshness window. This closes the SDK clock-skew rollout risk under the new Ingest contract.

Remaining rollout risks: The RUM-7F panel must gain the marker before rollout. RUM-7C real E2E remains independently open. Peak JS heap exceeds serialized buffer bytes because object/string/body copies coexist. `npm audit --omit=dev` reported zero production dependency advisories at review time.

The 202 boundary also governs hard-navigation continuity. If `pagehide` occurs before the first acknowledgement is processed, no replay identity is carried forward; an old chunk might still have been accepted by Storage, but the browser cannot prove it. After a confirmed root, later unconfirmed pages are excluded from persisted counts. Held-response browser tests cover these cases in Chromium, Firefox and WebKit. This preserves the no-payload-persistence rule and avoids treating a beacon or request dispatch as durability.
