# Architecture and security review

Scope: approved Visual Replay v1, high risk, security-sensitive / architecture-change.

Architecture: existing rrweb capture, chunk contracts, object storage and BFF/player separation remain. New code belongs to replay modules and static artifact build; no direct backend fetch, proxy, auth or resource persistence was added. The mirrored policy is intentional for independent capture/playback boundaries and has byte-for-byte alignment verification plus an actual sanitized SDK fixture consumed by player tests. New production CSS-tree is pinned; its build/source-map dependency is fixed to source-map-js 1.2.2 in lockfiles. Runtime configuration is public and resolved at startup, not frozen in CI. SDK has no local Harness kernel; its review remains manual following the RUM-7E convention.

Security: visual mode is explicit, text masked by default, private mirror ancestry and form values excluded before buffering. Public selectors cannot unmask private roots or forms. URL policy validates exact origins, credentials, protocol, recursive image URLs and permitted public query keys; stylesheet parsing handles escapes and keeps safe empty rules for removed at-rules/selectors so later CSSOM indices remain aligned. Generated text, arbitrary functions, raw malformed nodes, resource-bearing forbidden values and event handlers are dropped. Sanitized visual attributes include removals, so invalid replacements cannot retain unsafe state. Scripts, unsafe embedded DOM and SVG foreignObject are excluded; pointer/scroll data is numeric and privacy-scoped.

Player validates every incoming chunk structurally and independently filters CSS/DOM/resources before rrweb. Operator CSP allows only approved HTTPS resources and exact bundled module paths; parent/player hostnames cannot be resource hosts. Browser isolation and sentinel-session rejection are preserved. The hostile fixture reaches no resource endpoint; the positive fixture loads only its three approved asset paths with no Authorization, preserves masked text and selected public heading, renders grid/colors/image/font and applies CSSOM changes during playback. Cross-origin CSS/font/image loads require public CORS and are not a guarantee that browser asset-host cookies are absent. No replay credentials or backend grants are provided to the runtime.

Boundaries: asset hosts are explicitly trusted to serve public presentation resources; CSS/class/id can carry application data and must be configured accordingly. Resources remain mutable; signed/private URLs are unsupported. No claim of deployed proxy or real Ingest/Storage E2E proof is made. New dependency alert was fixed; pre-existing Next/Zod advisories are recorded in implementation-summary.md and do not justify unrelated upgrades in this task.

Result: no remaining blocking finding introduced by this implementation within its approved scope. Full checks and remaining deployment limitations are recorded in implementation-summary.md.
