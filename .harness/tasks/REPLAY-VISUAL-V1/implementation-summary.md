# Visual Replay v1 — implementation and verification

Implemented only in sentinel-sdk-js and sentinel-rum-frontend. User approval and compiled high-risk route are recorded in plan.md. No backend endpoint, data schema, credential, quota, or resource-storage change.

SDK visual opt-in captures sanitized source CSS and visual DOM attributes, SVG shapes, empty form controls, pointer/scroll/resize and CSSOM mutations. Exact resource origins and configurable text masking are local developer configuration. Legacy mode and masking defaults remain. Computed presentation is a fallback for unreadable stylesheets. The parser rejects generated text, executable/unknown CSS functions, unsafe URLs, arbitrary query data, handlers and unsafe tags before retention. Next image-optimizer nested URLs and common font/resource queries are validated. Private roots/form values win over public text selectors. Attribute removal and invalid resource replacement clear stale state.

Transport now gzip-compresses a frozen JSON chunk once and reuses its bytes for retry. Decoded and wire limits are enforced separately without increasing either policy cap. Identity fallback remains available. Replay stop/expiry/disable also prevents further retries. CSS parser, admission and layout modules load lazily with Replay; core bundle remains under its existing budget (232,645 raw / 69,956 gzip in the final full run).

The static player independently filters visual data before rrweb. REPLAY_RESOURCE_ORIGINS grants only exact HTTPS resource origins, bounded to 20, excluding dashboard/player hostnames even on other ports. Scripts remain limited to five bundled modules; connect/forms/objects/media/workers remain denied and iframe sandbox/auth/session protections are unchanged. There are six fixed bootstrap files including index.html. Public origins are resolved at startup and do not require image rebuild. Parser JS is bundled at build; the packaged server needs neither esbuild nor CSS-tree at startup.

Verification: SDK npm run verify passed 98 unit/contract tests and 187 browser tests (2 Chromium-only metrics skipped on Firefox/WebKit), type/lint/source/build/package and bundle budgets. Frontend build/type/lint, 42 unit tests, architecture/security scripts, checkpoint/security/UI enabled/disabled/denied/corrupt/BFF and new real-SDK CSS/grid/font/image/mutation playback passed. Packaged-runtime smoke served all six files with runtime CSP and no dashboard secrets or build dependencies. Actual Docker daemon image build and deployment were not performed. The pre-existing test-only incremental addEvent experiment still reports UNRELIABLE; production continues bounded reconstruction, as documented previously.

The new CSS parser exposed source-map-js 1.2.1 advisory GHSA-68fv-2mgg-jv7q. Both lockfiles now resolve the compatible fixed 1.2.2; targeted parser, package and isolated visual tests passed afterward. Existing frontend Next 16.3.6 and Zod 4.6.5 versions were not changed; their pre-existing audit alerts remain outside this feature. No new advisory is accepted for the added parser dependency.

Deployment: publish/consume a new SDK release, enable replay.visual and exact resourceOrigins, deploy the frontend image to dashboard/player, set matching REPLAY_RESOURCE_ORIGINS on the player, and permit anonymous CORS on public asset hosts. Generate new recordings. Source CSS/class/id values must be public presentation data. Resources are referenced, not archived; updates/removal/CORS can change old playback. External font requests may identify the player origin as Referrer, but tests show no Sentinel authorization or captured-page URL. Browser cookies belonging to approved resource domains may apply; dedicated public asset hosts are preferred.

Limitations: generated CSS text, constructed/adopted stylesheets, shadow DOM, frames and canvas/media remain excluded. Existing byte/depth/privacy limits still bound fidelity. This does not claim pixel-perfect support for every web surface or retroactive restoration of old recordings.
