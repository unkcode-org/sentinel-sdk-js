# RUM-TARGET-1.1 TDD plan — one rage-click semantic

Status: **SDK-only implementation verified; no deploy**. Follow `docs/RUM-INTERACTION-ATTEMPTS-design.md` and the brief in this directory. No new RUM event type.

1. Keep the current three-browser real-pointer baseline for enabled/disabled native buttons with direct/span text. Add failing tests for disabled presses producing one `rage_click` from three qualifying pairs, with `tag`/`role`/approved text and no fabricated click/dead-click. Enabled versions must keep the same click, rage, and dead-click counts/payloads.
2. Add browser fixtures for `aria-disabled` controls, supported roles, unroled div/span/img, nested targets, multiple child elements, and click/no-click mixtures. Assert grouping uses stable logical element identity and normalized radius <= 0.04 in a 1,000 ms attempt-time window. Generic targets must never include `label`/`text` under the current contract.
3. Add state-machine boundary tests for matching `pointerId`, target continuity, movement/drag, scroll/touch gestures, `pointercancel`, long press, non-primary pointer, multi-touch, target removal/replacement/reparenting, route change, and shutdown. Reject ambiguity and prove active/provisional/history caps and cleanup.
4. Add correlation tests for immediate/delayed native click, keyboard click without pointer pair, untrusted/synthetic events, late click, and paired click followed by another attempt. Assert exactly one rage sample per action. Preserve current `onClick`/dead-click semantics and the existing immediate click-only rage behavior.
5. Add privacy tests for private control/ancestor/descendant, sensitive fields and labels, contenteditable, hidden/inert regions, deep/large DOM, unsafe and oversized strings. Inspect complete serialized RUM batches. Keep TARGET-1 8/12/20/160/80 limits and no unrestricted `textContent`/`innerText` reads.
6. Implement bounded pointer pairing and the measured 32 ms click correlation in SDK only. Keep the existing `rage_click` wire type and legacy `click_count` field, now documented as attempt count. Do not add target state fields in this slice. Run focused Chromium/Firefox/WebKit tests, full `npm run verify`, performance/bundle checks, and `git diff --check`.
7. If separately approved, implement optional boolean `target.disabled` and `target.aria_disabled` end to end with strict applicability/value validation and historical absence handling. Test Storage, Ingest, Query, frontend, and SDK contracts. Roll out Storage, then Query/Ingest compatibility, frontend, and SDK emission last. Do not deploy under this task.

Acceptance includes unchanged physical `rage_click_count`/`has_rage_clicks` aggregation and unchanged click/dead-click counts, with documented historical coverage differences for rage. The interaction semantics and generic-target privacy boundary are approved for step 6; each new target field still requires separate approval before step 7.
